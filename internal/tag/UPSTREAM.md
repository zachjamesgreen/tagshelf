# internal/tag

A local copy of [github.com/dhowden/tag](https://github.com/dhowden/tag), an MP3 (ID3v1, ID3v2.2/2.3/2.4), MP4 (AAC, M4A, ALAC), OGG, FLAC and DSF metadata parsing library. Upstream has been inactive since 2024, so tagshelf carries the code itself and changes it as needed.

## Source

- Repository: https://github.com/dhowden/tag
- Commit: `3d75831295e8` (2024-04-17)
- License: BSD 2-Clause, Copyright 2015 David Howden (see `LICENSE`, which must stay with this code)

The commit "Import github.com/dhowden/tag at 3d75831 verbatim" holds the unmodified upstream files, so local changes can always be reviewed with:

```console
git diff <that commit> -- internal/tag
```

Dropped from upstream: `cmd/` (demo CLIs), `go.mod`, `go.sum`, `README.md` (replaced by this file) and the upstream CI/editor files (`.github/`, `.travis.yml`, `.editorconfig`).

## Usage

Detect and parse tag metadata from an `io.ReadSeeker` (i.e. an `*os.File`):

```go
m, err := tag.ReadFrom(f)
if err != nil {
	log.Fatal(err)
}
log.Print(m.Format()) // The detected format.
log.Print(m.Title())  // The title of the track (see Metadata interface for more details).
```

Parsed metadata is exported via a single `Metadata` interface, giving a consistent API for all supported formats. `Raw()` exposes the underlying tag names, which are not consistent across formats. `Sum` computes a metadata-invariant SHA1 checksum of the audio data only. The `mbz` subpackage extracts MusicBrainz identifiers from the raw tags.

## Local changes

Changes made after the import, newest first:

- Tests: `TestReadFrom` accepted `ErrNoTagsFound` from every sample, so it passed when nothing was read; it now takes that error only from the untagged MP3 and also compares `Format` and `FileType`, and a failure names the file and the field. `testdata/with_tags/sample.id3v22.mp3` was a copy of the ID3v2.3 sample: it is now a real ID3v2.2 tag, built by hand to the specification with a `PIC` frame and `UFI` / `TXX` MusicBrainz IDs (see `testdata/README.md`; `TestID3v22Sample`, and `TestExtractID3v22Sample` in `mbz`). `TestReadID3v1Tags` compares every field of the six ID3v1 samples. `TestFuzz`, which asserted nothing, is now `FuzzReadFrom` in `fuzz_test.go`, a Go fuzz test over `Identify`, `ReadFrom`, every getter and `Sum`, seeded with every fixture and sample, each also cut short and damaged, and with crafted files of each format; `sum_test.go` now holds tests of `Sum`. `TestSumOGGPinned` pins the OGG hash and `TestSumDiffersWithTheAudio` changes a byte of the audio of a fixture of every format. `craft_test.go` builds tags byte by byte for the tests of damaged files and of the forms Picard, iTunes and foobar2000 write (`TestID3v2PicardForms`, `TestMP4iTunesForm`, `TestVorbisFoobar2000Form`); no file those programs wrote was at hand, so these follow the specifications. Also new: tests of pictures in every format, UTF-16 frames, extended headers, frame flags, URL and binary frames, Opus, `SumASF` with a Data Object of size 0, and `Identify`.
- `sum.go`, `apev2.go`, `dsf.go`: `SumAtoms` hashes the payload of every `mdat` atom, in file order; it used to stop after the first, so a fragmented MP4, which has one `mdat` for each fragment, was hashed by its first seconds alone and two files that start alike formed an exact duplicate group. After the first `mdat` an atom that cannot be read ends the walk and is not an error, so a file with one `mdat` hashes as before whatever follows it. **The sum of an MP4 file with more than one `mdat` changes once**; all other MP4 sums are unchanged. A FLAC stream behind an ID3v2 tag is read with `ReadFLACTags` and hashed with `SumFLAC`: it used to be read as an MP3, without its Vorbis comments, and hashed with its FLAC metadata blocks, so a retag changed its hash. **The sum of such a file changes once**, to that of the same stream with no ID3v2 tag. New `SumDSF` hashes the payload of the `data` chunk of a DSF file, where `Sum` used to hash the whole file, tag included (`.dsf` is not a supported extension, so the index holds no DSF sums), and a DSF file with no ID3v2 chunk returns `ErrNoTagsFound`. `SumAll` returns its read error; it returned `""` and `nil`. `Sum` no longer has the branch that called it, which could not be reached. Tests: `sum_test.go`, `TestFLACBehindID3v2`.
- `id3v1.go`, `tag.go`, `id.go`, `ogg.go`, `wav.go`: ID3v1 text ends at the first NUL of its field and is decoded as UTF-8 when it is valid UTF-8 and as Windows-1252 otherwise, as the WAV INFO reader does; it used to be returned as raw bytes, which are not valid UTF-8 for anything but ASCII, with whatever followed the NUL. A file shorter than the 128 bytes of an ID3v1 tag, and an Ogg stream that ends without a comment packet, return `ErrNoTagsFound`; they returned a seek error and `io.EOF`. `Identify` leaves the reader where it was; for an ID3v1-only file it left it 3 bytes in. A WAV file whose ID3 chunk cannot be read is read from its LIST/INFO chunk, and the chunk's error is returned only when there is none. Tests: `id3v1_test.go`, `id_test.go`, `TestShortFileHasNoTags`, `TestOGGWithoutComment`, `TestReadWAVUnreadableID3Chunk`.
- `vorbis.go`, `flac.go`: a FLAC Vorbis comment or PICTURE block is read whole (a block is at most 16 MiB) and taken apart in memory, and every length inside a block or an Ogg comment packet is checked against what is left of it. The picture's data length used to be allocated before any of it was read, up to 4 GiB for a file of 90 bytes, and a damaged vendor or comment length loaded the rest of the file. A comment with no `=`, a `METADATA_BLOCK_PICTURE` that is not base64 and a picture that cannot be read are left out; each used to make the file unreadable. A picture type above 20 has no name and is kept. The values of a key written many times are joined once at the end; joining them as they came took time quadratic in their number. `Year` reads the leading year of `DATE` with `leadingYear`, or else of `YEAR`: any `DATE` not of 4, 7 or 10 characters read as year 1, so `2001-05-12T10:30` was filed under `Album (1)`. `leadingYear` (`apev2.go`, shared by the ID3v2, APEv2 and WAV readers) now takes the first four digits of any date that starts with a year, `yyyyMMdd` included. `AlbumArtist` also reads `ALBUM ARTIST`. Tests: `vorbis_read_test.go`.
- `mp4.go`: the atom reader is rewritten. It loops over the atoms, entering `moov`, `udta`, `meta` and `ilst` without recursion: 3,300,000 nested empty atoms (26 MB) overflowed the stack. It reads 64-bit atom sizes (size field 1) and atoms that run to the end of the file (size field 0), as `SumAtoms` does; an `mdat` with a 64-bit size before `moov` used to hide the tags without an error. Every size is checked against what is left of the file: a tag atom that runs past it is an error and any other ends the read, where a damaged size used to load the rest of the file. An item is read whole and taken apart in memory, and one that cannot be decoded is left out; it used to make the file unreadable. The getters check the type of the stored value, which is whatever class the `data` atom declares, and a freeform (`----`) atom named like one of the reader's own keys (`trkn_count`, `©nam`, …) is not stored: either could make `Title`, `Artist`, `Year`, `Track` or `Disc` panic. A text item with several `data` atoms keeps every value, NUL-separated, in `Raw`, and the getters return the first; the second atom's header used to come back inside the string. Text of class 2 (UTF-16) is decoded. `trkn` and `disk` numbers are 16 bits (track 300 of 400 read as 44 of 144) and a `trkn` with no total is read. A cover is told by its first bytes, or else by its class (JPEG, PNG, GIF, BMP). Integer atoms are read in full: `tmpo` used to read as its high byte. `FileType` is `M4A`, `M4B` or `M4P` by the major brand of `ftyp`, and still empty for other brands; it was always empty, so the index's format column was. `atoms.Name` returns the names in sorted order, so a file with both `©ART` and `©art` reads the same artist (that of `©ART`) on every run. Tests: `mp4_read_test.go`.
- `id3v2.go`, `id3v2frames.go`, `id3v2metadata.go`, `util.go`: the frame reader is rewritten. `ReadID3v2Tags` reads the tag whole, or as far as the file goes, and takes it apart in memory, with every size checked against what is left of the tag: a damaged frame size used to load the rest of the file, and an unsynchronised tag was read with one read call for each byte. A frame that runs past the tag ends the read; a frame that cannot be decoded is left out and the frames after it are read, where it used to make the file unreadable. ID3v2.4 unsynchronisation is undone frame by frame on the stored bytes, when the tag header or the frame asks for it, and a data length indicator is skipped and not taken for the size: such tags lost every frame after the first with a stuffed byte, which a JPEG cover always has. ID3v2.4 frame sizes written as plain 32-bit numbers, as old iTunes did, are read as such when only that reading is followed by a frame, padding or the end of the tag. A frame of size 0 is skipped; only a name starting with a zero byte is padding. Compressed and encrypted frames are left out, as their bytes were never decoded. The loop no longer counts the tag's header against its size, which stopped it 10 bytes early and lost a short last ID3v2.2 frame. Frames of one name are numbered with a counter; finding a free number from 0 each time took 83 seconds for 40,000 frames. A text frame keeps the NULs between its values, so `Raw` holds every value of an ID3v2.4 frame and the getters return the first; they used to be run together. Text labelled ISO-8859-1 is decoded as Windows-1252. A UTF-16 description ends at a zero code unit at an even offset (encoding 2 with ASCII text always failed), and an odd last byte of UTF-16 text is dropped. `Year` falls back to the year frame of the other versions (`TDRC` in a 2.3 tag, `TYER` in a 2.4 one) and reads `2001 ` and `20010512` as 2001. A `PIC` format in upper case gives its MIME type. An extended header is still an error when it runs past the tag. Tests: `id3v2_read_test.go`, `id3v2_test.go`, `id3v2metadata_test.go`.
- `asfwrite.go`: new `WriteASFAttribute` copies a WMA (ASF) file with one text attribute set in the Extended Content Description Object, for the manual marker, which go-taglib drops. It removes every attribute of that name (case-insensitively) from each ECD object, appends the new one to the first, and creates the object (adding 1 to the header count) when there is none. Only the Header Object changes: a Padding Object with room absorbs the size change, or else the header grows or shrinks and the Data Object and index objects are copied after it byte for byte. The ECD size and count, the Header Object size and the File Properties File Size (set to the new file's real length, as TagLib and mutagen leave it stale) are rewritten; File ID is left alone. Files with a Digital Signature Object, the Broadcast flag or a Data Object size of 0 are refused with `ErrASFRefused`, and nothing is written for any file that does not check out. Tests: `asfwrite_test.go`.
- `apev2write.go`, `apev2.go`: new `WriteAPEv2Tags` sets or removes text items of the APEv2 tag of an `*os.File` in place, for tagging .aac on its APEv2 side. The new tag replaces the old one where it was, or else goes at the end before any ID3v1 tag, with a header and footer (version 2000); the leading ID3v2 tag, the audio and ID3v1 tags are left byte for byte, so `Sum` is unchanged. Keys match case-insensitively and are written in the caller's case; other items, binary ones included, keep their order, and a second item whose key differs only in case is dropped. Bad keys or values, or a damaged tag, are refused before anything is written. The item parser moved out of `readItems` into `parseAPEv2Items`, and `findTrailingTags` also returns where the tag starts. Tests: `apev2write_test.go`, and `internal/tagwrite`.
- `vorbis.go`: a FLAC or OGG comment key written more than once keeps every value. `Raw` joins them with NUL in the order they appear, as the ASF reader does, so `mbz` reads every artist and album artist ID Picard or go-taglib writes as repeated `MUSICBRAINZ_ARTISTID` comments; it used to keep only the last. `Title`, `Artist`, `Year` and the other getters return the first value where they used to return the last. Tests: `vorbis_test.go`, and the multi-valued artist ID round trip in `internal/tagwrite`.
- `wav.go`, `apev2.go`, `sum.go`, `tag.go`: WAV, APE, MPC and .aac (ADTS) files are read, and `Sum` hashes only their audio, so a retag keeps it. `ReadWAVTags` reads the ID3v2 tag in an `ID3 ` or `id3 ` chunk with `ReadID3v2Tags`, and takes each field it lacks (title, artist, album, year, track, genre, comment) from a LIST/INFO chunk, decoded as UTF-8 or else Windows-1252; with INFO alone the format is the new `INFO`. `ReadAPEv2Tags` reads the APEv2 tag at the end of the file (new format `APEv2`), also when ID3v1 tags sit after it, before it (as mutagen leaves them) or both. Keys match case-insensitively and `Raw` keeps each key's own case, so `mbz` reads Picard's MusicBrainz keys. An APE or MPC file with a leading ID3v2 tag reads its APEv2 tag, since TagLib never updates that ID3v2 tag; it used to read the stale ID3v2 values. An .aac file with a leading ID3v2 tag still reads it, as go-taglib writes .aac that way. New file types `WAV`, `APE`, `MPC` and `AAC`. `SumWAV` hashes the `data` chunk payload without its pad byte (to the end of the file when its size is unknown); `Sum` used to hash whole WAV files. For every other file hashed from the start or after a leading ID3v2 tag (MP3, APE, MPC, AAC), `Sum` now leaves out a trailing APEv2 tag and an ID3v1 tag on either side of it; it used to leave out only a final ID3v1 tag, so the APEv2 tag counted. WAV, APE, MPC and .aac sums change once, as do MP3 sums of files with an APEv2 tag. `Identify` does not know the new formats. Lyrics3v2 tags are not skipped. Tests: `wav_test.go`, `apev2_test.go`, `sum_retag_test.go`, `mbz/mbz_test.go`.
- `asf.go`, `tag.go`, `id.go`, `sum.go`, `mbz`: WMA (ASF) files are read. `ReadFrom` and `Identify` report format `ASF` and file type `WMA`; they used to return `ErrNoTagsFound`. The reader takes title and artist from the Content Description Object (Raw names `Title`, `Author`, `Copyright`, `Description`, `Rating`) and every attribute of the Extended Content Description Object and of the Metadata and Metadata Library objects in the Header Extension, including `TAGSHELF_MANUAL`. Attribute names match case-insensitively. Raw values are strings (text; WORD, DWORD and QWORD as decimal; BOOL as `true`/`false`; GUIDs as `XXXXXXXX-XXXX-…`), with an attribute written more than once joined with NUL and a value repeated verbatim kept once; byte arrays are `[]byte`, the first only. `WM/TrackNumber` may be text (`N` or `N/M`) or a DWORD, with the zero-based `WM/Track` as a fallback; `WM/PartOfSet` gives the disc; `WM/Year` reads its leading year; `WM/Picture` is the picture. `mbz` reads Picard's ASF names (`MusicBrainz/Track Id` is the recording, `MusicBrainz/Release Track Id` the release track, and `MusicBrainz/Album Id`, `Release Group Id`, `Artist Id`, `Album Artist Id`). `Sum` hashes only the Data Object's packets (from 50 bytes into it to its end, or to the end of the file for a size of 0), so a retag keeps the hash; it used to hash the whole file. WMA files with MusicBrainz IDs now qualify for the library, and every WMA sum changes once. Tests: `asf_test.go`, `mbz/mbz_test.go`.
- `vorbis.go`, `id3v2metadata.go`: FLAC and OGG `TRACKNUMBER` and `DISCNUMBER` written as `N/M` read as N, with M as the total unless `TRACKTOTAL` / `DISCTOTAL` is set; they used to read as 0. ID3v2 years written as an ISO 8601 timestamp other than `yyyy` or `yyyy-MM-dd`, such as the v2.4 `TDRC` values `1997-05` and `1997-05-12T10:30`, read as their year; they used to read as 0. MP3 albums tagged that way gain a `(Year)` folder on the next reorganize. Tests: `vorbis_test.go`, `id3v2metadata_test.go`.
- `sum.go`: `Sum` hashes only the audio frames of MP3 files, so adding, editing or removing ID3v2 or ID3v1 tags keeps the hash. `SumID3v2` used to seek back to byte 0 and hash the ID3v2 tag too. It also skipped an extended header twice and ignored the 10-byte v2.4 footer (flag `0x10`). It now skips `10 + synchsafe size`, plus 10 for a footer. `SumID3v1` and `SumID3v2` used to drop the last 128 bytes whether or not they were a tag. Now they drop them only when they start with `TAG`. Every MP3 sum changes once. The fallback for formats `Sum` does not recognise (WAV, WMA, APE, MPC, .aac without ID3v2) goes through `SumID3v1`, so those now hash to the end of the file too. FLAC, OGG and MP4 sums are unchanged. Tests: `sum_retag_test.go`.
- `sum.go`: `Sum` hashes only the audio of OGG files and of every MP4 brand, so a retag keeps the hash. MP4 used to take the atom path only for brand `M4A `, and OGG always hashed the whole file. The new `SumOGG` hashes every packet except the Vorbis comment and `OpusTags` headers, so page sequence numbers, CRCs and page boundaries, which shift when the comment changes size, do not count. `SumAtoms` also reads 64-bit atom sizes (size field 1) and an `mdat` that runs to the end of the file (size field 0), which large M4B files use. FLAC, MP3 and M4A sums are unchanged. Tests: `sum_retag_test.go`.
- `mbz`: `Extract` returns an `IDs` struct with named fields (`RecordingID`, `ReleaseTrackID`, `AlbumID`, `ReleaseGroupID`, `ArtistIDs`, `AlbumArtistIDs`) in place of `Info` and its string keys. The old `Track` / `Recording` keys held different IDs per format. Now UFID, MP4 `MusicBrainz Track Id` and Vorbis `MUSICBRAINZ_TRACKID` are the recording, and `MusicBrainz Release Track Id` / `MUSICBRAINZ_RELEASETRACKID` the release track, as Picard writes them. Key names and TXXX descriptions match case-insensitively (TagLib writes them upper case). Values are split on NUL, `/` and `;`; the single-valued IDs keep the first part. Raw tags are read in sorted key order, so the same key wins on every run. The Vorbis reader still keeps only the last of repeated keys, so FLAC/Ogg artist ID lists hold one ID until that reader fix. `MUSICBRAINZ_RECORDINGID` is also read as the recording. The AcoustID, disc ID and TRM keys are no longer read. Tests: `mbz/mbz_test.go`.
- `mp4.go`: freeform (`----`) values skip the 4-byte locale of their `data` atom; they used to start with four NULs. A `data` atom too short for those 8 bytes is skipped. Test: `mp4_freeform_test.go`.
- Import paths rewritten from `github.com/dhowden/tag` to `tagshelf/internal/tag`.
